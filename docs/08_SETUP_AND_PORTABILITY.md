# 08. Setup and portability (new machine, Linux or Windows)

This file answers two questions: what actually travels with `git clone`, and the exact commands
to get a working checkout on a second machine, Linux or Windows. Commands are given in pairs;
run the column for your OS.

## 1. What git carries and what it does not

| Travels with git | Stays behind, must be reacquired per machine |
|---|---|
| `src/`, `tests/`, `scripts/`, `configs/`, `docs/` (except `docs/reference/`), `notebooks/`, `README.md`, `the project rules`, `pyproject.toml`, `requirements.txt`, `requirements-colab.txt`, `.gitignore`, `.env.example`, `data/README.md`, `data/MANIFEST.json`, `weights/README.md`, `reports/README.md` | `.venv/` (recreate from `requirements.txt`), `data/raw/`, `data/interim/`, `data/processed/` (redownload and reconvert), `weights/<RUN_ID>/` (redownload from Drive), `reports/` (regenerated by runs), `.env` (never committed, recreate from `.env.example`) |

**Dataset size is not a git problem, on purpose.** `.gitignore` ignores everything under `data/`
and `weights/` except their `README.md` and `MANIFEST.json`. Trying to add `data/raw/dhakaai/train.rar`
(1.44 GB) is a no-op: `git status` will not even list it, `git add` on it silently does nothing
unless forced. Even without that rule, GitHub itself hard-blocks any single file over 100 MB on
push and warns at 50 MB, so a raw dataset archive could never be committed by accident. Only the
hash and licence metadata (`data/MANIFEST.json`, a few KB) is tracked, never the archive.

## 2. Prerequisites per OS

| | Linux (Ubuntu/Debian shown; adapt the package manager) | Windows |
|---|---|---|
| Python 3.10 | `sudo apt install -y python3.10 python3.10-venv` (add the deadsnakes PPA first if 3.10 is not offered: `sudo add-apt-repository ppa:deadsnakes/ppa && sudo apt update`) | `winget install Python.Python.3.10` (or the installer from python.org; tick **Add python.exe to PATH**) |
| Git | `sudo apt install -y git` | `winget install Git.Git` (installs Git for Windows, which bundles the `sh` this repo's `.git/hooks/pre-commit` needs; no extra step) |
| ffmpeg (optional, for manual clip inspection) | `sudo apt install -y ffmpeg` | `winget install Gyan.FFmpeg` |
| Disk | Tens of GB free for raw plus converted datasets | Same |

Verify before continuing:

```bash
# Linux
python3.10 --version   # 3.10.x
git --version
```

```powershell
# Windows (PowerShell)
py -3.10 --version     # 3.10.x
git --version
```

## 3. Clone the repository

Use your own GitHub account here; the SSH deploy key set up for this session's agent access is
not needed on a normal machine where you can log in interactively.

```bash
# Linux
git clone git@github.com:dilconkihoro/traffic-incident-detection.git
cd traffic-incident-detection
git config --local user.name "<your name>"
git config --local user.email "<your email>"
```

```powershell
# Windows (PowerShell)
git clone git@github.com:dilconkihoro/traffic-incident-detection.git
cd traffic-incident-detection
git config --local user.name "<your name>"
git config --local user.email "<your email>"
```

If SSH is not set up on the new machine yet, clone over HTTPS instead and authenticate with a
personal access token when prompted (never the account password, GitHub no longer accepts it):

```bash
git clone https://github.com/dilconkihoro/traffic-incident-detection.git
```

The repo-local `.git/hooks/pre-commit` guard (checked into no branch; it is local-only, so a
fresh clone will not have it) is optional on a normal machine; it exists to stop this specific
dev session from ever committing under the wrong account. Skip it unless you want the same
belt-and-braces check, in which case copy it from this machine.

## 4. Create the virtual environment and activate it

Activation is the one step that genuinely differs by OS and shell.

```bash
# Linux / macOS, bash or zsh
python3.10 -m venv .venv
source .venv/bin/activate
```

```powershell
# Windows, PowerShell
py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
```

```cmd
:: Windows, cmd.exe
py -3.10 -m venv .venv
.venv\Scripts\activate.bat
```

```bash
# Windows, Git Bash
python -m venv .venv
source .venv/Scripts/activate
```

**PowerShell execution policy:** if `Activate.ps1` is refused with a script-execution error, that
is Windows' default policy, not a problem with this repo. Allow it for the current session only:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

Your prompt should now show `(.venv)`. Everything below assumes it is active; on Windows,
`python` inside the venv is `.venv\Scripts\python.exe` and matches the Linux commands one for one.

## 5. Install the pinned requirements

Identical command on both platforms. The pin file's own `--extra-index-url` line points at the
PyTorch CPU wheel index, which publishes Windows wheels for the exact pinned version
(`torch==2.14.0+cpu`, confirmed to exist as a `win_amd64` wheel, checked 2026-09-22), so nothing
Windows-specific needs to change here.

```bash
pip install -r requirements.txt
pip install -e . --no-deps
```

## 6. Set up `.env`

```bash
# Linux / macOS / Git Bash
cp .env.example .env
```

```powershell
# Windows, PowerShell
Copy-Item .env.example .env
```

```cmd
:: Windows, cmd.exe
copy .env.example .env
```

Then edit `.env` and set your own values. `.env` is git-ignored on every platform; never commit it
or paste its contents anywhere (the project rules security rule).

## 7. Verify the checkout

```bash
pytest -m "not target" -q       # must be green
pytest -m target -q             # white-box rule tests; green once Phase 2 code is present
ruff check . && ruff format --check .
python -c "import trafficwatch; print('import ok')"
```

These commands are identical on Windows once the venv is active; there is no `.venv/bin` versus
`.venv\Scripts` distinction to make manually, `pytest`/`ruff`/`python` on `PATH` already resolve
to the venv's copies after activation.

## 8. Reacquiring data and weights on the new machine

Nothing under `data/` or `weights/` travels with git (section 1). On the new machine:

```bash
mkdir -p data/raw/ua-detrac data/raw/dhakaai        # Linux
```

```powershell
New-Item -ItemType Directory -Force data\raw\ua-detrac, data\raw\dhakaai   # Windows PowerShell
```

- **DhakaAI:** identical command on both platforms, it is a plain Python script:
  ```bash
  python scripts/acquire_datasets.py fetch-dhakaai --dry-run
  python scripts/acquire_datasets.py fetch-dhakaai --retrieved <YYYY-MM-DD>
  ```
- **UA-DETRAC:** manual on both platforms, same steps (`docs/03_DATA_PIPELINE.md` section 9):
  download from `https://sites.google.com/view/daweidu/projects/ua-detrac`, or the Kaggle mirror
  with your own `KAGGLE_USERNAME`/`KAGGLE_KEY`.
- **Checking a downloaded archive's hash by hand**, if you ever need to compare outside the script:
  ```bash
  sha256sum data/raw/dhakaai/train.rar               # Linux, Git Bash, WSL
  ```
  ```powershell
  Get-FileHash -Algorithm SHA256 data\raw\dhakaai\train.rar   # Windows PowerShell
  ```
- **Weights:** download the run's export zip from Drive (`MyDrive/tid/export/<RUN_ID>.zip`,
  produced by `notebooks/colab_train.ipynb`) and unzip it to `weights/<RUN_ID>/` so it contains
  `best.pt` and `model_card.json` (`docs/04_COLAB_TRAINING.md` section 9).

## 9. Common Windows-specific gotchas

| Symptom | Cause | Fix |
|---|---|---|
| `Activate.ps1 cannot be loaded because running scripts is disabled` | Default PowerShell execution policy | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` (section 4) |
| `python` or `py` not found | Installer did not add Python to `PATH` | Reinstall with **Add python.exe to PATH** ticked, or use the full path to `python.exe` once |
| Line-ending warnings on `git status` or `git diff` | Git for Windows defaults to CRLF conversion on checkout | Harmless for this repo (Python and Markdown tolerate LF); set `git config --global core.autocrlf true` once if the warnings bother you |
| `git commit` runs an unfamiliar `sh` hook without complaint | Git for Windows bundles its own `sh.exe` and runs POSIX hooks (like `.git/hooks/pre-commit`, if you copied it) through it automatically | Nothing to do; this is expected, not a bug |
| A path under `data/processed/` exceeds Windows' old 260-character limit | Long-path support is off | Enable it once, as admin: `New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force`, or keep the repo close to a drive root (e.g. `C:\dev\traffic-incident-detection`) |
| `pip install opencv-python` seems to hang or is slow | Usually just a large wheel over a slow connection, not Windows-specific | Wait it out, or retry with `pip install --default-timeout 60 --retries 5 -r requirements.txt` |

## 10. What never differs by OS

The rules in `the project rules` and this repo's `the project rules` apply identically on Windows: never commit
`.env`, never commit data or weights, no em dashes, stage files by name (`git add <path>`, never
`git add -A` or `git add .`), no `Co-Authored-By` trailer, never push unless asked. None of that
is platform-specific and none of it needs a different command on Windows.
