# 08. Setup and portability (Windows, primary; Linux and macOS also covered)

Every section below leads with the Windows command and gives the Linux/macOS equivalent alongside
it for reference. This file covers the complete path from a bare Windows machine to a running
system: what to install, how to get the code and data, and how to run the pipeline end to end.

## 1. What git carries and what it does not

| Travels with git | Stays behind, must be installed or reacquired per machine |
|---|---|
| `src/`, `tests/`, `scripts/`, `configs/`, `docs/` (except `docs/reference/`), `notebooks/`, `README.md`, the project rules, `pyproject.toml`, `requirements.txt`, `requirements-colab.txt`, `requirements-webapp.txt`, `.gitignore`, `.env.example`, `data/README.md`, `data/MANIFEST.json`, `weights/README.md`, `reports/README.md` | Python itself, Git itself, the `.venv/` folder (recreated from `requirements.txt`), `data/raw/`, `data/interim/`, `data/processed/` (redownloaded and reconverted), `weights/<RUN_ID>/` (redownloaded from Drive), `reports/` (regenerated by runs), `.env` (never committed, recreated from `.env.example`) |

**Dataset size is not a git problem, on purpose.** `.gitignore` ignores everything under `data/`
and `weights/` except their `README.md` and `MANIFEST.json`. A raw dataset archive (over a
gigabyte) is never committed by accident: `git status` will not even list it, and GitHub itself
hard-blocks any single file over 100 MB on push regardless. Only the hash and licence metadata
(`data/MANIFEST.json`, a few KB) is tracked, never the archive.

## 2. Prerequisites

| | Windows | Linux (Ubuntu/Debian shown) |
|---|---|---|
| Python 3.10 | `winget install Python.Python.3.10` (or the installer from python.org; tick **Add python.exe to PATH**) | `sudo apt install -y python3.10 python3.10-venv` (add the deadsnakes PPA first if 3.10 is not offered) |
| Git | `winget install Git.Git` (Git for Windows; bundles a `bash`/`sh` that can run this repo's shell scripts and its optional `pre-commit` hook) | `sudo apt install -y git` |
| 7-Zip (needed to open the `.rar` dataset archives; Windows has no built-in `.rar` support) | `winget install 7zip.7zip` | `sudo apt install -y unrar` or `p7zip-full` |
| ffmpeg (optional for the CLI, only needed to assemble your own sample clips from raw frames; **required** for the web dashboard in `webapp/`, section 14, which uses it to make the annotated video playable in a browser) | `winget install Gyan.FFmpeg` | `sudo apt install -y ffmpeg` |
| Node.js 20+ (optional, only for the web dashboard in `webapp/`, section 14; not needed for the CLI) | `winget install OpenJS.NodeJS.LTS` | `sudo apt install -y nodejs npm` (or use `nvm` for a current LTS) |
| Disk | Tens of GB free for raw plus converted datasets | Same |

Verify before continuing:

```powershell
# Windows (PowerShell)
py -3.10 --version     # 3.10.x
git --version
7z            # confirms it is on PATH; any output is fine
node --version        # only if you plan to run the web dashboard, section 14
```

```bash
# Linux
python3.10 --version   # 3.10.x
git --version
node --version         # only if you plan to run the web dashboard, section 14
```

## 3. Clone the repository

Use your own GitHub account and your own credentials here.

```powershell
# Windows (PowerShell)
git clone <repository-url>
cd traffic-incident-detection
git config --local user.name "<your name>"
git config --local user.email "<your email>"
```

```bash
# Linux / macOS
git clone <repository-url>
cd traffic-incident-detection
git config --local user.name "<your name>"
git config --local user.email "<your email>"
```

Git will prompt for a personal access token as the password on the first push (GitHub no longer
accepts account passwords over HTTPS). If you prefer SSH, generate a key with `ssh-keygen` and add
it under GitHub Settings, SSH and GPG keys, then clone with the `git@github.com:...` form instead.

## 4. Create the virtual environment and activate it

```powershell
# Windows, PowerShell
py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
```

```cmd
:: Windows, cmd.exe
py -3.10 -m venv .venv
.venv\Scripts\activate.bat
```

```bash
# Windows, Git Bash, or Linux / macOS
python3.10 -m venv .venv   # on Windows Git Bash, use: python -m venv .venv
source .venv/bin/activate  # on Windows Git Bash, the path is .venv/Scripts/activate
```

**PowerShell execution policy:** if `Activate.ps1` is refused with a script-execution error, that
is Windows' default policy, not a problem with this repo. Allow it for the current session only:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

Your prompt should now show `(.venv)`. Everything below assumes it is active.

## 5. Install the pinned requirements

Identical command on every platform. The pin file's own `--extra-index-url` line points at the
PyTorch CPU wheel index, which publishes Windows wheels for the exact pinned version, so nothing
Windows-specific needs to change here.

```bash
pip install -r requirements.txt
pip install -e . --no-deps
```

## 8. Get the datasets

```powershell
# Windows, PowerShell
New-Item -ItemType Directory -Force data\raw\ua-detrac, data\raw\dhakaai
```

```bash
# Linux / macOS / Git Bash
mkdir -p data/raw/ua-detrac data/raw/dhakaai
```

- **DhakaAI:** identical command on every platform, a plain Python script, no account needed:
  ```bash
  python scripts/acquire_datasets.py fetch-dhakaai --dry-run
  python scripts/acquire_datasets.py fetch-dhakaai --retrieved <YYYY-MM-DD>
  ```
- **UA-DETRAC:** manual on every platform (`docs/03_DATA_PIPELINE.md` section 9): download the
  images and train/test annotation XML archives from
  `https://sites.google.com/view/daweidu/projects/ua-detrac`, or use the Kaggle mirror with your
  own `KAGGLE_USERNAME`/`KAGGLE_KEY`. Move the downloaded files into `data/raw/ua-detrac/`, then:
  ```bash
  python scripts/acquire_datasets.py verify data/raw/ua-detrac/<file> --dataset ua-detrac --retrieval manual --source-url <url> --retrieved <YYYY-MM-DD>
  ```
- **Checking a downloaded archive's hash by hand**, if you ever need to compare outside the script:
  ```powershell
  Get-FileHash -Algorithm SHA256 data\raw\dhakaai\train.rar   # Windows PowerShell
  ```
  ```bash
  sha256sum data/raw/dhakaai/train.rar               # Linux, Git Bash, WSL
  ```
- **Weights (once available):** download the run's export zip from Drive
  (`MyDrive/tid/export/<RUN_ID>.zip`, produced by `notebooks/colab_train.ipynb`) and unzip it to
  `weights/<RUN_ID>/` so it contains `best.pt` and `model_card.json`
  (the Colab runbook section 9).

## 9. Run the CLI and the demo, start to end

The interface is a command line plus output files, not a window with buttons (decision D-13).

```bash
python scripts/fetch_standin_weights.py       # once: downloads the stand-in AI model
python -m trafficwatch run <video.mp4> --standin
```

The guided walkthrough script explains each step as it runs and needs no arguments:

```bash
./scripts/run_full_demo.sh
```

This is a bash script. On Windows, run it from **Git Bash** (installed as part of Git for
Windows in section 2), not from PowerShell or cmd.exe:

```bash
# Windows, in a Git Bash window, from the repo folder
bash scripts/run_full_demo.sh
```

Every run writes `reports/<run_id>/` with `incidents.csv`, `annotated.mp4`, `latency.json`, and
`run_manifest.json`. Open `annotated.mp4` in any video player and `incidents.csv` in any
spreadsheet application.

## 11. The full process, start to end, one screen

1. Sections 2 to 7 above: install, clone, set up.
2. Section 8: get both datasets.
3. Data conversion (built once both datasets are available; see `docs/03_DATA_PIPELINE.md`
   section 9): turns the raw archives into a training-ready dataset.
4. Section 10: run the Colab notebook, paste results back.
5. Once a trained model lands in `weights/<RUN_ID>/`: swap it in via `configs/pipeline.yaml`, no
   code changes needed, and rerun evaluation.
6. Section 9: run the CLI or the guided demo at any point along the way to see the system work.
7. Section 14, optional: run the web dashboard for a browser-based demo of the same pipeline.

the project guide explains what each of these pieces does in plain language, with a full
completion checklist by project phase and a glossary of terms.

## 12. Common Windows-specific gotchas

| Symptom | Cause | Fix |
|---|---|---|
| `Activate.ps1 cannot be loaded because running scripts is disabled` | Default PowerShell execution policy | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` (section 4) |
| `python` or `py` not found | Installer did not add Python to `PATH` | Reinstall with **Add python.exe to PATH** ticked, or use the full path to `python.exe` once |
| `bash: scripts/run_full_demo.sh: command not found` | Running it from PowerShell or cmd.exe, which do not understand `#!/usr/bin/env bash` | Run it from Git Bash instead: `bash scripts/run_full_demo.sh` (section 9) |
| `.rar` files will not open | Windows has no built-in `.rar` support | Install 7-Zip (section 2), then use it directly or via File Explorer's right-click menu |
| Line-ending warnings on `git status` or `git diff` | Git for Windows defaults to CRLF conversion on checkout | Harmless for this repo (Python and Markdown tolerate LF); set `git config --global core.autocrlf true` once if the warnings bother you |
| A path under `data/processed/` exceeds Windows' old 260-character limit | Long-path support is off | Enable it once, as admin: `New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force`, or keep the repo close to a drive root (e.g. `C:\dev\traffic-incident-detection`) |
| `pip install opencv-python` seems to hang or is slow | Usually just a large wheel over a slow connection, not Windows-specific | Wait it out, or retry with `pip install --default-timeout 60 --retries 5 -r requirements.txt` |

## 13. What never differs by OS

The rules in the project rules apply identically on Windows: never commit `.env`, never commit data or
weights, no em dashes, stage files by name (`git add <path>`, never `git add -A` or `git add .`),
no `Co-Authored-By` trailer, never push unless asked. None of that needs a different command on
Windows.

## 14. The web dashboard (optional, supplementary)

A browser UI (login, upload, live processing view, run history) also exists on top of the CLI,
built as a separate layer that calls the same pipeline (decision D-25). It is optional: the CLI in
section 9 is the official interface and works fully without it. Setup, tech stack, and running it
start to end are documented in `webapp/README.md`; the short version, once Node.js and ffmpeg are
installed (section 2, ffmpeg is required here even though it is optional for the CLI), is
installing the dashboard's own Python packages with `pip install -r requirements-webapp.txt`,
generating an admin login with `python scripts/set_admin_password.py`, then running the backend
(`uvicorn webapp.backend.main:app --reload --env-file .env --port 8000`) and the frontend
(`cd webapp/frontend && npm install && npm run dev`) at the same time.

Uploads over `TW_MAX_UPLOAD_FRAMES` (default 180 frames, about 7 seconds at 25fps) are rejected, so
a long video cannot quietly tie up a machine with no GPU for several minutes without warning. Only
one run executes at a time, at lowered priority on at most half the CPU cores, and any queued or
running run can be stopped with the Cancel run button on its Processing page.
